# Version 1.0 - Technical Build 1.0.21

Owner approved the local recurring-session QA candidate for production on 1 October 2026, before commits or deployment.

## Changes

- Existing session forms expose Repeat and an edit scope for recurring bookings: This session (default) or Full series.
- This session updates only the selected occurrence. Full series updates upcoming occurrences, preserving past, in-progress and Completed / Payment Collection records.
- Edit Repeat Until, extend a weekly series, shift upcoming dates, or switch Weekly to Once. Once retains the first upcoming occurrence. Shortening requires explicit confirmation naming the empty occurrences to cancel; history-bearing occurrences cannot be removed through a series edit.
- Convert an upcoming one-time session to Weekly without replacing its ID or roster. New occurrences get fresh IDs and never inherit attendance, receipts, notes or publication state.
- Validate the whole proposed edit before applying any part. Duplicate schedules, invalid/past dates, excessive ranges and recorded-payment financial-basis conflicts reject the entire batch.
- Preserve independent manual capacity, fees and rates unless explicitly changed; recalculate automatic values from bookings. Preserve physical court numbers, existing IDs and financial ownership. Ordinary extension never recreates cancelled gaps, and the original weekday survives independently moved occurrences.

A code rollback does not undo session edits or confirmed cancellations already made by users; data recovery requires separate investigation and approval. Do not restore production data automatically.
