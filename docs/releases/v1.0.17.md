# Version 1.0 - Technical Build 1.0.17

Owner approved the local QA candidate for production on 20 September 2026.

## Changes

- Payment-group Summary lists per-person charges, total charges, receipts and remaining dues. Due Reminder stays focused on pending items.
- The group Advances tab offers Latest Advances and Complete Summary, combining contributions and itemizing usage under each member.
- Advances from any active group member can cover the group's charges, oldest funding source first, with ownership and source allocations retained.
- While a shared Advance cycle has a positive balance, eligible activity payments and payment overages join Advance. The full activity contribution is shown, with the payer's own share counted once as usage; no duplicate receipt is created.
- Once Advance is exhausted, later contributions remain ordinary Credit until a new explicit Advance deposit. Known same-day transaction ordering is respected.
- Personal Advance summaries link to the shared statement when there is one unambiguous funded group. History retains original receipts and links activity contributions to the original activity.
- Summary previews scroll independently while tabs and copy actions remain accessible on mobile.
- Session completion checks reuse one ledger snapshot per check, avoiding repeated calculation during backup loading.

## Verification

- 216 automated regression tests passed before release preparation.
- Local replay of the owner-supplied backup verified source conservation and that statement generation does not mutate stored financial records.
- Regression coverage includes multiple contributors, exhausted/reopened cycles, same-day funding, rollover, own-share accounting, edits, deletion, reversal, overlapping groups and reload.
- Desktop, 390-pixel and 320-pixel summary checks passed; no browser warnings or errors were observed.
- Public source and Hosting assets exclude production backups, local QA bootstraps and credentials.

## Release Gates

The production release must pass the protected pull request's required test-and-build check, deploy Hosting only, and verify the public sign-in shell and deployed assets. Final commit, CI and Hosting evidence belongs in the GitHub release and approved release-tracking records.

## Compatibility and Rollback

No Firestore rules, schema or data migration is included. The existing build 1.0.16 cloud-save and recovery safeguards remain unchanged. Advance classification and allocation are derived from existing records; original receipts are not rewritten by a summary.

Rollback target: `v1.0.16`. Rebuild and deploy that tag's Hosting assets only. This restores the previous calculation semantics but does not reverse any user edits made after release. Any data recovery requires separate inspection and approval; never import a stale backup as part of a routine Hosting rollback.

The formal Jira/Confluence release remains **Version 1.0**. This patch does not create Version 1.1.
