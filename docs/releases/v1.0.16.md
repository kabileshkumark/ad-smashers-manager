# Version 1.0.16

## Changes

- Capture save data, revision, actor, and document IDs together before asynchronous requests.
- Stop stale saves and authentication callbacks when the session or loaded revision changes.
- Reject an empty replacement of a populated workspace and retain pending local changes.
- Reject incomplete or inconsistent collection loads instead of saving partial data.
- Require atomic, sequential, audited workspace saves in Firestore rules; block older save clients.
- Preserve pre-recovery local journals separately instead of replaying them across a recovery checkpoint.
- Include the app version, base revision, and write protocol in save audits.
- Remove an unverified data-integrity assurance from the loading-error screen.

## Verification

- 191 application regression tests passed.
- 19 synthetic Firebase Rules API cases passed, including role checks and unchanged planner access.
- Build and whitespace validation passed.
- A private recovery fixture completed load, payments rendering, ledger calculations, and save with no document deletions.

## Operations

The app and Firestore rules were deployed together on 19 September 2026 after owner approval. Older app versions cannot save through the new rules; users must reload the current release before editing.

Recovery approval, source data, database snapshots, and exact readback results are retained privately outside this repository. This release does not enable managed backups or point-in-time recovery. These safeguards prevent the reproduced unsafe writes; they are not a substitute for independent backups.
