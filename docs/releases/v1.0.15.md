# Version 1.0 - Technical Build 1.0.15

Owner-approved activity touch-scroll fix, 13 September 2026. Follow-up to the activity selection issue addressed in build 1.0.14.

## Cause and Correction

The previous fix kept player rows stable, but the shared keyboard handler still scheduled unconditional field centering and repeated it on visual viewport scroll events. Touch scrolling can leave an old input focused, so the focus check alone did not cancel those callbacks. Separately, scroll tracking reset the outer page to zero, conflicting with browser keyboard panning.

- Reveal an obscured input only within its own modal, nested list, or main content scroller, using the minimum movement needed.
- Cancel delayed automatic scrolling as soon as the user touches or scrolls, even if focus stays on the previous input.
- Update viewport geometry during panning without scheduling field recentering.
- Keep scroll tracking observational: do not reset the outer page during scrolling.
- Ignore callbacks for removed controls and avoid oscillating oversized text areas.
