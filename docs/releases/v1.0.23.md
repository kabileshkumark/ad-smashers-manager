# Version 1.0 - Technical Build 1.0.23

Owner approved the local booking-capacity QA candidate for production on 23 October 2026, before commits or deployment.

## Changes

- FR-SES-013: suggest capacity from original booking rows. With the default six players per two-hour court, each one-hour court contributes three places and each two-hour court contributes six. Two courts for two hours plus one court for either the first or last hour give 15 places, not 18.
- Other durations require explicit manual capacity; fractional places from custom settings are not rounded automatically. The existing setting is labelled Players per 2-hour Court.
- Preserve explicit manual capacity even when it equals the automatic suggestion. A saved capacityMode records manual or automatic intent. Reset restores a supported automatic suggestion; legacy saved capacities are not migrated or recalculated on load.
- Recurring edits retain per-occurrence manual capacities, apply automatic capacity to supported changed bookings and reject unsupported automatic changes atomically. Existing past-session and financial protections remain in force.
- FR-SES-023 / FR-SES-027: final lists retain joining order and print numbered blank places up to saved capacity. Draft versus Final status uses saved capacity or publication stage, not merely filled peak-court buckets.
- Full rotation, court grouping, attendance and waiting-list responses are unchanged. Removing an attendee does not remove waiting-list responses or add waiting players to payments.
- Keep the Capacity label readable next to its reset control on narrow phones.
