# Version 1.0 - Technical Build 1.0.14

Owner-approved activity touch and settled-player removal release, 6 September 2026. Tracking: ADS-20.

## Changes

- Activity player rows remain in a stable order; selection state updates in place without rebuilding the page or recreating the scroll container after every tap.
- Native selectors and non-text controls do not trigger keyboard-driven scrolling. Text and amount inputs retain keyboard visibility handling.
- A player can be removed from active lists when their own Due, remaining Advance, remaining Credit and reserved payment balances are zero. Another group member's due does not block a settled player's removal.
- Removal preserves sessions, attendance, activity shares, contributions, receipts, Advance/Credit ownership and historical group links. Removed players retain history access and a Restore action.
- Reopened balances remain visible. Historical activity editing, export/import and cloud reload preserve archived player identities.

## Verification

- 171 automated regression tests pass, including 10 new cases for selection stability, archival safety, group coverage, reopened balances, role coverage and cloud persistence.
- Production build and synchronized version files pass.
- Owner-approved local browser QA covered repeated selection, long lists, saved activity allocations, player removal, restore and unused-funds protection. Checked 320, 390, 430 and 1200 pixel viewport widths.
- Anonymous export-replay cases verified that removal leaves all financial snapshots and historical records unchanged. Private exports and the local-only harness remain outside Git and Hosting.

## Release Boundary

Deploy Firebase Hosting only. No production data import, bulk migration, Firestore rules, indexes or functions deployment is included. The formal release remains Version 1.0.

Player removal adds optional `archivedAt` metadata. The existing `archivedPlayers` collection stores removed directory entries; their ledger eligibility and referenced financial data remain intact. See [Player Lifecycle](../player-lifecycle.md).

Rollback source: `v1.0.13`. Rebuild that tag and redeploy Hosting. Hosting rollback does not undo user data edits. The older build does not honor `archivedAt` and may show removed players as active; redeploy this build to regain archive visibility rules. Financial identities and history must not be deleted to compensate.
